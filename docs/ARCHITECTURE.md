# Architecture — Sridevi Tours & Travels

Phase 01 lays down the foundation. This file records the boundaries later
phases build within.

## Layers

| Path                                            | Responsibility                                                                                        |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `src/app/[lang]/`                               | Routes. Every page sits under the locale segment (`/en`, `/te`).                                      |
| `src/proxy.ts`                                  | Redirects locale-less URLs using the `NEXT_LOCALE` cookie or `Accept-Language`.                       |
| `src/config/`                                   | Verified business facts (`site.ts`) and the typed service catalogue (`services.ts`). No presentation. |
| `src/i18n/`                                     | Locale config, dictionaries (`en.ts` is the type; `te.ts` must match it), server loader.              |
| `src/design/tokens.ts`                          | JS mirror of the CSS design tokens in `src/app/globals.css`.                                          |
| `src/components/ui/`                            | Primitives: Button, Section/Container, Typography, Form, Spinner, ServiceIcon.                        |
| `src/components/layout/`                        | Header, mobile navigation, language switcher, footer.                                                 |
| `src/components/home/`, `services/`, `contact/` | Page compositions.                                                                                    |
| `src/features/intro/`                           | Cinematic intro: constants, gate, store, master timeline, controller, preview scene.                  |
| `src/features/enquiries/`                       | Enquiry schema shared by client and future API.                                                       |
| `src/features/bookings/`                        | Booking status lifecycle and allowed transitions.                                                     |
| `src/features/payments/`                        | Payment method and verification types.                                                                |
| `src/server/`                                   | Server-only modules (`env.ts`). Database, auth and notifications go here.                             |

## Reserved boundaries (not implemented in Phase 01)

- **Enquiries API** — `src/app/api/enquiries/route.ts`, validated with `EnquirySchema`, issuing a unique reference (e.g. `SDT-YYMMDD-XXXX`).
- **Database** — `src/server/db/` (PostgreSQL). Store the minimum customer data, and no identity documents.
- **Auth** — `src/server/auth/`, admin-only, secret from `AUTH_SECRET`.
- **Admin dashboard** — `src/app/[lang]/admin/`, protected server-side (not only in `proxy.ts`).
- **Notifications** — `src/server/notifications/` (WhatsApp or SMS to the owner).
- **Payments** — `src/server/payments/`; verification happens on the server only.

## Business rules enforced by structure

- The service catalogue has no price or availability fields.
- `BookingStatus` can only reach `confirmed` from `payment_verified`.
- Government services are marked `assistanceOnly`, and the UI shows the assistance note.
- Enquiry forms hand off through WhatsApp or encoded default-mail/Gmail compose links. No server email service is configured, so the UI reports that an enquiry is ready, not sent.

## Intro timing

- The master timeline is built by `buildIntroTimeline`. It throws if its duration is not exactly 5.000 s.
- Asset preloading (logo, timeout 2.5 s) runs before the timeline starts and is not counted in the 5 s.
- The intro plays once per browser session, only when a visitor lands on a home URL. Reduced motion skips it entirely.
- A safety timer dismisses the overlay if anything stalls.
- `IntroPreviewScene.tsx` is a stand-in for Phase 01. Replace it in Phase 03 and keep the same refs.

## Phase 02 additions

- `src/config/media.ts`: photography slots (`MediaSlot`). Each slot uses an art-directed plate until a licensed image is added. See `docs/ASSETS.md`.
- `src/components/ui/MediaPlate.tsx`: renders a slot. Pass `fill` to cover a positioned parent.
- `src/components/ui/Reveal.tsx`: a one-time fade-up on scroll. It changes only opacity and transform, and is hidden only when `html[data-js]` is set. It has a 3 s CSS fallback and is turned off for reduced motion.
- `src/components/services/ServiceCard.tsx`: `ServiceFeatureCard` (travel, media) and compact `ServiceCard` (digital services). The details action opens a centered modal; cards do not expand inline.
- `src/components/contact/ContactChannels.tsx`: phone, WhatsApp and visit panels.
- Provisional icons: `src/app/{favicon.ico,icon.svg,apple-icon.png}`, generated by `npm run icons`.
- The dependency audit is in `docs/SECURITY.md`.

## Phase 03 additions

- **Design system:** the Luxury Dark palette lives in `globals.css` and `src/design/tokens.ts`. `tokens.test.ts` guards that the two match and that no beige or cream values return.
- **Surfaces:** `surface-charcoal | midnight | atmos | stone`, plus `glass`, `panel`, `sheen`, `vignette` and `grain`.
- **Service enquiries:** `src/features/service-enquiry/`.
  - `schema.ts` holds the enquiry kinds, field specs, Zod schemas and the WhatsApp message builder.
  - `ServiceModal.tsx` is the provider: one native `<dialog>` opened with `showModal()`, plus `ModalHeader`.
  - `ServiceModalTrigger.tsx` is a real link that opens the modal.
  - `ServiceEnquiryForm.tsx` and `ServiceFormFields.tsx` render the forms.
  - The provider wraps the page shell in `[lang]/layout.tsx`.
- **Service details:** `src/features/service-details/ServiceDetailsModal.tsx` renders one localized native dialog for the selected service. Its document lists and guidance come from `src/config/service-details.ts`; the WhatsApp action hands off to the service-enquiry modal.
- **Intro:** `IntroCinematicScene.tsx` (globe → airplane → train → coach and car → logo) replaces the Phase 01 preview scene. The timeline stays a single master timeline of exactly 5.000 s.
  - `elapsedMs` is measured from the timeline's true origin, captured on its first rendered frame.
- **Art:** `src/components/art/TravelArt.tsx` holds the vector vehicles and landmarks. `src/components/home/HeroScenes.tsx` composes them into scenes. `MediaSlot.scene` shows a scene until an `image` is supplied.
- **Logo:** `site.logo.transparent` switches the plaque off once a genuine transparent asset exists.

## Phase 03.1: dual theme

- **Default:** dark for every visitor. Light is only used after an explicit choice; the OS colour scheme is not consulted.
- **Theme code:** `src/features/theme/theme.ts` holds the key, a pre-paint `themeScript`, and the store and setter. `ThemeToggle.tsx` is the header button (moon in dark, sun in light, bilingual action labels).
- **No flash:** `themeScript` runs in `<head>` before first paint. The browser check confirms the first painted frame already uses the saved theme.
- **Token roles:** the approved dark values in `@theme` are unchanged. `:root[data-theme="light"]` remaps the palette roles (page bg, surfaces, text, accent), so every utility follows and no component is duplicated. Textured surfaces (glass, panel, stone, atmosphere, plates, header) have explicit light overrides.
- **Hero and card scenes** read `--scene-*` variables, so they render night skies in dark and daylight in light.
- **Intro:** the overlay carries `data-theme="dark"`, so it is always the dark cinematic cut. Its 5.000 s timeline is unchanged.

## Phase 03.2: reference-based light theme (now the default)

- **Default theme:** light for new visitors. CSS keys light on `:root:not([data-theme="dark"])`, so it also applies without JavaScript. A saved dark choice sets `html[data-theme="dark"]` before first paint and is respected on every visit.
- **Variants:** `light:` and `dark-theme:` are Tailwind custom variants (`globals.css`) for theme-specific refinements. Dark-mode styling is unchanged unless noted below.
- **Light palette roles:**

  | Role                               | Value                                                     |
  | ---------------------------------- | --------------------------------------------------------- |
  | Page background                    | `#FFFFFF`                                                 |
  | Soft background                    | `#F4F7FB`                                                 |
  | Atmospheric blue                   | `#DCE9F7`                                                 |
  | Text (navy / secondary)            | `#10213B` / `#42556B`                                     |
  | Borders                            | `#D7E0EA`                                                 |
  | Input borders                      | `#8494A8` (≥3:1)                                          |
  | Accent for text and buttons        | `#BF4E05` (4.9:1 on white)                                |
  | Bright decorative accent (`flame`) | `#F36B08`, the reference orange (3.0:1, so non-text only) |

- **Light hero:** `LightHeroPanorama` in `src/components/art/LightArt.tsx` is one sunrise scene with all five subjects. It renders with `meet`, sits between the text column and the preview cards, and uses charcoal outlines (the `outline` prop on `TravelArt`) for contrast. Dark keeps its per-slide night scenes. The carousel opens on slide 02, as in the reference.
- **Light service cards:** `LightServiceCard` uses two-tone `ServicePictogram`s (plane, train, bus, temple, digital). `LightServicesShowcase` is the five-card "Our Services" row on the home page. On the Services page the travel grid shows these cards in light and the dark feature cards in dark (CSS selects one).
- **Header:** a `1fr | auto | 1fr` grid inside a 90rem bar keeps the navigation centred on the whole header (measured within 2 px, both themes and languages, ≥1024 px). Zone widths fit by design: Call Us is icon-only below 1440 px, and the theme toggle shows only the active icon below 1280 px.
- **Dark-mode changes in 03.2 (all fixes):**
  - Header centring and compaction, as above.
  - Input borders use `--input-border` (≥3:1, previously ~1.7:1).
  - The selected trip-type option is clearer.
  - The hero text scrim mid-point goes from 45% to 60%, for legibility over the rail scene on slide 02.
  - The carousel opens on slide 02 (global).
